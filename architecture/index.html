Pi Home MCP 設計図

自宅の Raspberry Pi で MCP サーバーを動かし、Claude から家のサーバーやセンサーを安全に扱えるようにする。このページは設計を理解するための図解で、決まったことを反映しながら育てていく。

2接続方式

経路使える Claude届く範囲認証状態
① SSH + stdioDesktop / Code家の LAN 内SSH 鍵Phase 1
② HTTP + TailscaleDesktop / CodeTailscale に参加した端末Tailscale の端末認証Phase 3
③ HTTPS + Cloudflare Tunnelclaude.ai（Web・スマホ）インターネットOAuth 必須Phase 4

claude.ai のカスタムコネクタは Anthropic のクラウドから接続してくるため、Tailscale の内側には届かない。スマホから使いたい場合だけ③が必要になる。

4セキュリティ方針

  • 任意のシェルコマンドを実行するツールは作らない。
  • 操作系のツールは config.yaml の許可リストにある対象にだけ効く。
  • MCP サーバーは専用の低権限ユーザー mcp で動かす。Docker 操作に必要な権限だけを追加する。
  • まず読取ツールだけで運用し、操作ツールは1つずつ増やす。
  • 認証なしでインターネットに公開しない。③は OAuth を入れてから作る。

5ロードマップ

  1. PHASE 0
    手元の PC で雛形を作る 次にやるPi なしで FastMCP サーバーと get_system_status を作り、Claude Desktop / Code から呼べることを確認する。
  2. PHASE 1
    Pi に載せて SSH で接続Raspberry Pi OS を用意し、systemd 不要の stdio 起動で①の経路を通す。
  3. PHASE 2
    サーバー管理ツールを増やすDocker、ログ、サービス状態。操作系は許可リスト付きで追加する。
  4. PHASE 3
    センサー・家電と外出先接続BME280、カメラ、Wake-on-LAN、SQLite。HTTP 化して Tailscale（②）で外から使う。
  5. PHASE 4
    claude.ai からの接続OAuth を実装し、Cloudflare Tunnel（③）でスマホから使えるようにする。

6未決事項

  • Raspberry Pi 4 のメモリ容量とストレージ本体は自宅の Pi 4 を使う方針（実機で型番を要確認）。メモリ容量は未確認。常時稼働のため USB 接続 SSD からの起動を検討する。
  • 実装言語暫定で Python（FastMCP）。GPIO・センサーのライブラリが豊富なため。
  • Docker 権限の渡し方docker グループは実質 root 相当。sudoers で特定コマンドだけ許可する案と比較する。
  • 家電連携の手段SwitchBot API、Nature Remo、赤外線モジュール自作のどれにするか。
